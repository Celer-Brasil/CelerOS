# tools/ - host-side Python/shell/Node tooling

## OVERVIEW
Host utilities: device control over serial (`celerctl`), the JS app linter (`app_lint`), the LAN OTA test server, the hub publisher, data-partition flashing, and asset generators. It is a distinct domain (score ~9; own `requirements.txt`). Docs: `README_USBTOOL.md`, `README_OTA.md` (both also in `.pt-BR`).

## CONVENTIONS
- The generators are manual steps, not part of `idf.py build`. Commit their outputs (`data/icons/`, `SplashLogo.h`).
- `celerctl` defaults to the UART (CH340, `/dev/ttyUSB0`) through SerialLink. On boards built with `CELEROS_USB_NATIVE` (watch) it talks to CDC1 instead; on `CELEROS_LINK_ON_USJ` boards (dog) it shares the USB-Serial/JTAG with the console. With WiFi up it also speaks HostLink over TCP (`CELEROS_DEBUG_BRIDGE`, port 5555; token AUTH + UDP discovery — see README_USBTOOL "Celer Debug Bridge"). `-b` sets the baud (warning-only on USB-native ports, no-op on TCP).
- Bridge tokens (`~/.config/celerctl/tokens.json`) are cached by address AND by device identity: the banner/probe carry the board MAC (`DebugBridge.cpp` `macId`, pre-AUTH) as `id:<mac>` keys, so DHCP IP changes self-heal (auth retries the identity token and re-keys; `devices` marks `(pareado)` and heals the cache during listing). Firmware without the id field just skips the matching. `pair` also accepts `-p`. Serial probes run under a watchdog: a UART stuck in `open()` (board replugged mid-scan) is reported and skipped, never hangs `devices`.
- The littlefs size is read from `partitions_{16MB,4MB,32MB}.csv`, which is the single source of truth. Never duplicate it in scripts.
- `flash_data.sh` minifies the app `.js` in the stage (`sdk/lib/minify_apps.js`: jsstrip --min, --top for non-main, free-names reserved — the same format the hub publishes; `test.js` is dropped). LittleFS spends one 4 KB block per file, and the CYD/cyd-vspi 768 KB image only fits with minified source; the repo keeps the readable source and jsmin preserves line breaks.
- CLI help and output text are Portuguese.

## DEVICE DIAGNOSTICS (BENCH)
- **`celerctl logcat` does NOT show the boot log.** The `esp_log` hook lives in `SerialLink`, installed only after `FileSystem::init` — so ROM bootloader, partition table, the SD mount and every driver that comes up before the filesystem never reach the ring. On 2026-10-18 both 4848s came back without `/sd` and `logcat` showed nothing; `failed to mount card (13)` (FatFs `FR_NO_FILESYSTEM`, exFAT card) only appeared on the raw UART at 115200. When a boot failure is the question, use `celerctl monitor PORT --reset --out boot.log` (raw serial, no HostLink, no `idf.py monitor` fighting for the port).
- `celerctl doctor` is the ONE stop for "is this bench able to flash and publish": version in both CMakeLists, the embedded OTA pubkey vs the private key outside the repo, dep drift, sdkconfig drift, and every connected board with its chip. It reads only; exit 1 means do not publish or flash over anything. Run it before a bench session and after any IDF change.
- `celerctl ota check [FILE]` redoes on the PC what the device does before installing: downloads the channel's `update.json`, verifies the ECDSA P-256 signature against `main/OTA/OtaPublicKey.h`, the firmware sha256 and the `app_desc` version, and checks the chip against the connected board. Without a file it walks the whole hub path — the exact trip the device takes. `--json` for scripts. This is the fastest way to see "the hub published a manifest the devices will refuse".
- **The board guard on `ota push` refuses a bin built for another chip** (it reads `chip_id` from the image header, `tools/fw_image.py`). `--force` overrides; on the bench that should never be needed. A wrong-chip image is the one OTA mistake that ends in USB recovery.
- The debug bridge accepts ONE celerctl session per target; the second gets `bridge ocupado por outra sessao celerctl`. `pgrep -af celerctl` before benching — parallel sessions (human + other agents) are routine here. `logcat` holds the bridge while it runs; to observe without holding it, read the persisted logs afterwards: `celerctl shell "cat /local/log/kern.log"` (uptime-stamped per boot; HttpClient logs EVERY request with status/bytes/ms — first stop for "app nao baixa") and `/local/log/apps.log` (`celerctl crash` summarizes the last app death). Mind the LogPersist flush: the on-disk file only gets lines when the window opens (screen blank, no audio, no SD scan — writing flash with the RGB panel lit scrambles the frame), so with the screen on `kern.log` LAGS by minutes; `logcat --dump` (ring) is the live view and `/local/notifications.txt` is written immediately.
- `celerctl debug --app <Nome> --eval "<expr>"` evaluates ONCE in the live app (pauses at global(), runs in app scope, resumes and exits). Blocking Net calls work inside the eval — use it to measure a real fetch on the device (e.g. `Net.download` of a hub file) instead of guessing from the PC.
- `screencap` takes the output path positionally (`screencap /tmp/t.png`; there is no `-o`). `tap X Y` uses PHYSICAL pixels of the glass (480x480 on the 4848; the footer "Recarregar catalogo" button sits at y≈451).
- Device shell has no flag-style arguments (`ls -la`, `tail -n` fail with "caminho invalido") — use `cat <path>` and filter on the host; `df /local` works; quotes are not parsed.
- LittleFS fills up silently on the bench (3.4 MB partition, dozens of test apps installed): `df /local` before installs/pushes. The App Store reload alone needs ~180 KB free (see data/AGENTS.md "HUB CATALOG").

## ANTI-PATTERNS
- Replacing icon art by editing `data/icons/` directly. Delete `icons_src/<id>.png` and/or edit `icons.json`, then rerun `make_icons.py`. A hand-made 512px PNG in `icons_src/` is respected.
- Editing `tools/studio` build outputs (`.studio/build/**`, generated `main.js`/`game.data.js`) by hand: they are regenerated from `celergame.project.json` + `Assets/**`; change the source project and rebuild (or use an op).
- Committing `__pycache__/`.
- Running `celerctl` while `idf.py monitor` holds the same port.
- Expecting `celerctl logcat` to show a boot failure. It cannot: the `esp_log` hook is installed by `SerialLink`, after `FileSystem::init`. Use `celerctl monitor PORT --reset --out boot.log` for the raw boot (ROM bootloader, partition table, SD mount).

## STORE PACKAGE + DEPLOY LIMITS (hub gate e bancada, 2026-10-18)
- O pacote do hub e **FLAT**: extras = arquivos na raiz do app apenas (≤16 arquivos, ≤256 KB no total, ≤128 KB cada; .js/.png/.wav/.qoa/.json/.bin/.sh). Subpastas (`assets/`) NUNCA sobem — arte de jogo vai na raiz (padrao `ai_atlas.png`/`ai_bg.png` gerado por text2d/texture2d, key magenta 0xF81F) e o `E.init({bases:[...]})` aponta para a raiz.
- Teto de tamanho: .js enxuto do app **+ modulos das deps** > 64 KB exige `requires: ["psram"]` (teto absoluto 1 MB); `app.json` aceita **no maximo 8 deps** — agrupe cerebro com `celeros.game.kit` (puxa `celeros.game.rpg` = stats+inv+script).
- Apps NAO-jogo tem a familia **CelerKit** (`celeros.app.*`) no mesmo dir: core com loop de telas/overlays + fmt/path/semver/data/history/net/caps/events/text/input/form/list/launch/ai/chat/updater/fsx/svc/mesh/kit. `celer.js new Nome --appkit` scafolta com o pacote `celeros.app.kit` (8 deps numa). Doc: `Documentation/App_Kit_Guide.md` (+pt-BR); gates em `test/sdk/celerosapp_r1.js`.
- `celerhub publish` so sobe arquivos COMMITADOS (arvore suja recusa) e o hub recusa downgrade de versao — suba `version` + changelog. **REGRA: mudanca de app ou de dep so esta pronta com bump + publish no hub** (app: `celer.js publish <Pasta>`; dep: bump do `version: 'x.y.z'` no modulo + `publish-dep <arquivo>.js`); fix commitado sem publish nao chega a nenhum device — `celerhub list`/`deps-status` mostram o que ficou para tras. `celerhub publish-pending` fecha o buraco que esses dois deixavam aberto: eles comparam a versao DECLARADA, entao uma tarde editando o `main.js` sem bumpar nao acusava nada; o `publish-pending` compara o md5 do `main.js` enxuto (o mesmo que o hub guarda) e sai 1 apontando o proximo patch. Apps de `boards/<b>/data/apps` ficam de fora (sao de fabrica, entram pelo `flash_data.sh`; `--board-only` os inclui). `celerhub bump <pasta>` escreve a versao nova no `app.json` e no `PROJECT_VER` do app de uma vez. **Nao entra no CI** (precisa do hub e de token): rode antes do push junto com o `deps-status`.
- A loja serve URLs **absolutas** (meta/app/icon) e o app.json publicado leva campos computados (`size`, `md5`, `published_at`, `publisher`, `zip`); `celerctl apps store` aceita os dois formatos e tira os campos antes do lint (`_hub_url`).
- **Apps/deps privados**: `celerhub publish --private [--tenant T]` e `publish-dep --private [--tenant T]`. O hub os guarda fora do mount publico; a loja do device os le com `/local/hub_token.txt` (token com escopo `private`; o App Store 2.9.4+ anexa `?token=` nas URLs do hub). Sem o arquivo, o catalogo publico continua identico — e um app publico NAO pode depender de dep privada (o hub recusa no publish). **Do PC** o caminho existe tambem: `celerctl apps store PKG` resolve o token em `--hub-token`, `CELER_HUB_TOKEN` ou no `/local/hub_token.txt` do proprio device (antes nao havia token nenhum no celerctl e o app privado respondia "nao esta no hub"); `celerhub list` com token mostra os privados marcados. `celerctl apps install PASTA` grava o `app.json` por ULTIMO — se um modulo falha no meio (ACK perdido com o app rodando), o device continua anunciando a versao antiga e o erro manda fazer `shell "exit"` e repetir, em vez de deixar "app.json novo + modulo velho" no disco. `apps run` aceita pasta, sufixo, nome de exibicao ou o packageName inteiro (`celeros.vertical.app`); `pull`/`rm` seguem exigindo a pasta real (destrutivos).
